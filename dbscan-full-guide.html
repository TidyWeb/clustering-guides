DBSCAN: clusters that follow crowded places.

DBSCAN groups points that sit in crowded areas and links crowded areas that touch. Points out on their own are labelled noise instead of being forced into a group. You do not choose how many clusters to find; you choose what counts as "crowded". This guide uses one small map of pothole reports from start to finish: first as a picture, then as a calculation, then as Python code. Return to the clustering overview, continue to the HDBSCAN full guide, then compare with the K-Means full guide.

36

reports, no group labels

What DBSCAN will add: a label for every report. Reports in a crowded area get a cluster number (0, 1, …). Reports that are not part of any crowded area get -1, meaning noise. Noise is not a cluster; it is DBSCAN saying "this one does not belong anywhere".

How is this different from K-Means?

K-Means and DBSCAN answer different questions.

K-Means asks you set K

"Split these points into exactly K groups, each gathered round a centre." You must say how many groups there are before it starts. Every point is put in a group, even a point far from everything. It will always hand back K groups, even when the data has no real groups at all.

DBSCAN asks you set eps and min_samples

"Where are the points packed closely together?" You say what counts as "close" and "packed", and DBSCAN works out how many groups that gives. A group can be any shape. Points in empty space are left out as noise. If nothing is packed closely enough, it finds no groups.

So DBSCAN removes K-Means' biggest weakness, having to know the number of groups in advance. But it does not look at the data "with no settings". It swaps K for two other settings, and the number of groups it finds changes when they change (Section 06). What it gives you in return is the freedom for groups to be any shape and the ability to say "these points belong nowhere".

Can you run DBSCAN first, before K-Means? Yes, as a first look, and it is a sensible habit. It can show you whether there are crowded areas at all, roughly how many, what shape they are, and which points are isolated. Two cautions. First, its answer depends on eps, so it is a clue, not proof. Second, a DBSCAN count is not automatically the right K: on this map DBSCAN finds 2 groups, yet K-Means with K = 2 still cuts both roads in the wrong place, because the roads are curved and K-Means can only draw straight boundaries (Section 09). If DBSCAN shows curved or oddly shaped groups, keep DBSCAN. If it shows compact, round groups, K-Means with that K is worth trying.

Typical uses real work

  • Map hotspots: crime, accidents, taxi pick-ups or reports that bunch along streets and junctions.
  • Finding unusual cases: the noise points themselves are often the interesting output: odd transactions, faulty sensor readings.
  • Irregular shapes: any data where groups curve, stretch or wrap around each other.

What it is not common confusion

  • It is not classification: there is no answer column to learn from.
  • It does not need a number of clusters, but it still needs two settings (Section 06).
  • Noise does not mean "wrong data". It means "not in a crowded area at these settings".

03One
neighbour-
hood

Draw a circle, count what is inside

DBSCAN never looks at the whole map at once. It asks one small question about each point in turn: how many points lie within a set distance of this one? That distance is called EPS (short for epsilon, a small distance). In Python code it must be written in lower case, eps, because Python treats capitals as different letters. The circle of radius EPS around a point is its neighbourhood.

EPS = 0.7 km  ·  min_samples = 4
a point is core if its circle holds at least min_samples points, counting the point itself

The count for R04, worked out

Measure the straight-line distance from R04 to every other report, exactly as in the K-Means guide: square the gaps across and up, add them, take the square root. Here are the seven nearest:

04Core,
border,
noise

Every point gets one of three roles

DBSCAN checks the EPS neighbourhood around each point. The local count gives it a density role: core, border or noise. These roles describe how points relate to dense areas.

Core example label 0

A crowded point. It belongs to a cluster and can extend it: every point inside its circle joins the same cluster. R04 (count 5) is core.

Border example label 0

Not crowded itself, but inside the circle of a core point. It joins that cluster but cannot extend it. R01 (count 3) sits at the end of a road inside a core point's circle.

Noise example label -1

Not crowded, and not inside any core point's circle. It stays unassigned. R02 (count 1) has nobody nearby.

Roles describe density; labels name groups. On the map above, core point R04 and border point R01 both belong to cluster 0, so both have label 0. Core point R07 and border point R03 both belong to cluster 1, so both have label 1. Noise point R02 has no dense connection to a core point, so scikit-learn gives it label -1. Core and border do not have fixed label numbers: 0 and 1 identify clusters, not roles.

05Growing
clusters

Start at a crowded point and keep spreading

DBSCAN goes through the points in table order. When it meets a core point that is not in a cluster yet, it starts a new cluster and spreads outwards: every point in that core point's circle joins, and every one of those that is also core spreads the cluster further (Ester et al., 1996).

01

Next point

Take the next point in the table that has no cluster yet.

02

Count

Count the points in its EPS circle, itself included.

03

Too few?

Mark it noise for now. A cluster may still reach it later.

04

Enough?

Start a new cluster and add everything in its circle.

05

Spread

Repeat step 4 from every core point added, until no core point can reach further.

06

Finish

Anything still marked noise keeps the label -1.

the
settings

No K to choose, but two settings instead

DBSCAN does not ask how many clusters you want. The number of clusters comes out of the two settings, eps and min_samples, and it can change a lot when they change. Here is the same map with four values of EPS and min_samples held at 4.

Every report is noise.

Roads break into pieces.

EPS = 0.7 2 clusters · 4 noise

One cluster per road.

EPS = 1.2 1 cluster · 4 noise

The roads merge.

The dashed circle in the corner of each panel shows the size of EPS at that setting. Too small and nothing is crowded; too large and separate roads join up (scikit-learn user guide).

min_samples: how crowded is crowded?

Holding EPS at 0.7 km and changing min_samples:

Reports along these roads are about 0.3 km apart, so an EPS of 0.7 km reaches two reports each way: at most five points in any circle. Ask for six and nothing can ever be core, so everything becomes noise. Larger min_samples makes DBSCAN stricter and more resistant to noise; it is usually raised for bigger or noisier datasets. There is no universal rule. The original paper suggested 4 for two-dimensional data as a starting point (Ester et al., 1996).

A clue for EPS: the k-distance chart

For every point, measure the distance to its 4th nearest point (counting itself, to match min_samples). Sort those distances and plot them. Points inside crowded areas have small values; points out on their own have large ones. Where the curve turns sharply upward is a sensible place to try EPS.

The bend is a clue, not an answer. On real data the curve can bend gently or more than once. Try a few values near the bend, look at the maps, and keep the one whose clusters make sense for the question you are asking. Section 10 shows how to draw this chart with scikit-learn's NearestNeighbors.
07Units
and
distance

EPS only means something in the data's units

EPS is a distance, so it is measured in whatever units the columns use. On this map both columns are kilometres, so "0.7" means 0.7 km in every direction. Suppose the north column had been recorded in metres instead:

How the columns are measuredEPSClustersNoise
east in km, north in km0.724
east in km, north in metres0.7036
both standardised (StandardScaler)0.724

With north in metres, two reports on the same road are hundreds of "units" apart vertically, so no circle of radius 0.7 contains anything but its own centre: all 36 reports become noise. The data did not change; only the ruler did.

Same units? keep them

When the columns share a real unit, as map positions do, keep that unit. Then EPS has a plain meaning ("reports within 0.7 km") that you can explain to the council.

Different units? scale first

With columns like spend in pounds and visits per year, there is no shared unit, so standardise them first with StandardScaler. EPS is then measured in standard deviations (a standard deviation is roughly the typical distance of a value from its column's average; see the glossary). Here, standardising happens to give 2 clusters and 4 noise at EPS 0.7, but only because both columns already had similar spreads (1.42 and 1.15 km).

Always check EPS against the units you actually fed in. A setting copied from a tutorial or another dataset is meaningless until you know what one unit of distance means in yours.
08Where it
struggles

Four ways DBSCAN can mislead you

DBSCAN copes with curved shapes and noise, which K-Means cannot. It has its own blind spots, and each one comes from the same place: one EPS and one min_samples are applied to every part of the data.

1. Groups with different densities

A new dataset: a tight group of 22 points on the left and a spread-out group of 22 points on the right. No single EPS suits both.

EPS = 0.3 1 cluster · 22 noise

EPS 0.3: tight group gives 1 cluster; spread group gives 0 clusters and all 22 of its points are noise.

EPS = 0.6 4 clusters · 8 noise

EPS 0.6: tight group gives 1 cluster; spread group gives 3 clusters and 8 of its 22 points are noise.

EPS = 0.9 2 clusters · 1 noise

EPS 0.9: the two groups merge into one cluster; 1 spread point left as noise.

Small EPS finds the tight group but calls the spread group noise. Medium EPS breaks the spread group into pieces. Large EPS finds the spread group but merges it with the tight one. This is the main reason HDBSCAN exists (Section 12).

2. Bridges between groups

Two groups joined by a line of points. Whether they merge depends on whether the line is crowded enough to contain core points (EPS = 0.5, min_samples = 4):

Sparse chain 2 clusters

Sparse chain, gaps 0.4 km: 2 clusters; chain points: 1 core, 2 border, 2 noise.

Dense chain 1 cluster

Dense chain, gaps 0.2 km: 1 cluster; chain points: 10 core, 0 border, 0 noise.

A thin line made mostly of border and noise points cannot carry a cluster across, because only core points extend a cluster. That protects DBSCAN from the worst "chaining" effect. But a line of core points, such as a busy road between two towns, joins everything it touches into one cluster.

3. Many columns dimensions

With many columns, distances between all pairs of points become similar, so it gets hard to find an EPS that separates crowded from empty. Reduce the number of columns first, or choose a distance that suits the data. scikit-learn's clustering comparison warns that 2-D intuition may not carry over to high dimensions.

4. Border points and row order small print

As Section 05 showed, a border point within reach of two clusters joins whichever reaches it first. Results can differ slightly if the rows are shuffled. The number of clusters and the core points do not change; a few edge points can.

10DBSCAN
in Python

The whole route in pandas and scikit-learn

Four short blocks, using the same 36 reports from pothole_reports.csv (download it next to your notebook). The file also has a street column that the model is not given; we use it only at the end to check the result.

Reading the code. Lines starting with # are comments: notes for people, which Python ignores. Every line below has one. Words in highlighted code are explained in the notes beside each block, and all new terms are in the glossary at the end.

Block 1: load the reports

# pandas: the library for tables of data
import pandas as pd
# DBSCAN: the clustering method from scikit-learn
from sklearn.cluster import DBSCAN
# NearestNeighbors: finds the closest points to each point
from sklearn.neighbors import NearestNeighbors

# read the CSV file into a table (a DataFrame)
reports = pd.read_csv("pothole_reports.csv")

# keep only the two position columns, as an array of numbers
# (scikit-learn models take an array as input)
X = reports[["east_km", "north_km"]].to_numpy()

Read down the code

  1. Import DBSCAN, and NearestNeighbors for the k-distance chart.
  2. Load the same table as Section 01.
  3. Select only the two position columns. Both are in km, so no scaling is needed (Section 07).

Block 2: the k-distance clue for EPS

# how many points make a crowd (counting the point itself)
min_samples = 4

# fit = give the neighbour finder our points to work with
nn = NearestNeighbors(n_neighbors=min_samples).fit(X)

# for every point: distances to its 4 nearest points
# (the nearest is always the point itself, at distance 0)
# the _ throws away a second result we do not need
distances, _ = nn.kneighbors(X)

# [:, -1] = every row, last column (the 4th nearest)
k_dist = distances[:, -1]
k_dist.sort()   # smallest to largest

# show the 8 largest, rounded to 2 decimal places, as a list
print(k_dist[-8:].round(2).tolist())

Read down the code

  1. Find each point's 4 nearest points. The first is always the point itself, matching how min_samples counts.
  2. Keep the last column: the distance to the 4th nearest.
  3. Sort and look at the largest values. Plot the whole of k_dist to get the chart in Section 06.
[0.89, 0.93, 0.94, 0.98, 1.5, 1.74, 1.85, 1.88]

The last eight values jump well above the rest, which stay below 0.7: the same bend as the chart in Section 06.

Block 3: fit DBSCAN and count the result

# set EPS and min_samples, then fit = run DBSCAN on our points
# (eps must be lower case in code)
db = DBSCAN(eps=0.7, min_samples=4).fit(X)

# labels_ holds one label per report:
# 0, 1 ... for clusters, or -1 for noise
labels = db.labels_
reports["cluster"] = labels   # add the labels as a new column

# set() keeps each different label once;
# -1 is noise, not a cluster, so take 1 off the count
n_clusters = len(set(labels)) - (1 if -1 in labels else 0)
# count how many labels equal -1
n_noise = (labels == -1).sum()
# core_sample_indices_ = row numbers of the core points
n_core = len(db.core_sample_indices_)
print(f"clusters: {n_clusters}, noise: {n_noise}, core: {n_core}")

# show the report names of the noise rows
print(reports.loc[labels == -1, "report"].tolist())

Read down the code

  1. Fit with the two settings chosen in Section 06. There is no K.
  2. Attach each report's label to the table: 0, 1, … for clusters, -1 for noise.
  3. Count clusters without counting -1 as a cluster.
  4. List the noise reports so a person can look at them.
clusters: 2, noise: 4, core: 28
['R02', 'R06', 'R10', 'R28']

Block 4: check the clusters against the streets

# crosstab = a count table: streets down, labels across
# DBSCAN never saw the street column; we use it only to check
print(pd.crosstab(reports["street"], reports["cluster"]))

Describing clusters good practice

  • Report the size of each cluster and how many points are core versus border.
  • Describe the shape and extent ("a 3 km curved stretch"), not a centre: a curved cluster's average position can lie off the road entirely.
  • Check the result at nearby settings (EPS a little smaller and larger). If the clusters change completely, say so.

Reading the noise label -1

  • Always report how many points are noise and what share of the data that is.
  • A small amount of noise is often the most useful output: here, the four one-off reports might need a separate visit.
  • A very large share of noise usually means EPS is too small, min_samples too large, the units are wrong, or the data has no crowded areas at all.
Clusters describe, they do not explain. A cluster of reports along Mill Lane shows that reports crowd there. It does not show why: heavy traffic, poor drainage and more people walking past to report potholes would all produce the same picture.
12HDBSCAN
and
OPTICS

When one EPS is not enough

Section 08 showed DBSCAN's biggest weakness: one EPS for the whole dataset. Two related methods in scikit-learn remove that limit. Both keep DBSCAN's ideas of crowded points and noise.

HDBSCAN no EPS

Effectively tries every EPS at once and keeps the clusters that last longest as EPS changes, so tight and spread-out groups can both be found in one run. You mainly set min_cluster_size. A good first choice when densities vary (HDBSCAN reference, user guide).

OPTICS an ordering

Orders the points so that crowded areas sit next to each other and produces a "reachability" chart, from which clusters at different densities can be read off. Useful for exploring how the structure changes with density (OPTICS reference, user guide).

SituationTry first
Crowded areas of similar density, noise to leave out, a sensible distance unitDBSCAN
Crowded areas of very different density, or no idea what EPS should beHDBSCAN
You want to see how groupings change across densitiesOPTICS
Compact round groups and a known number of themK-Means
13Check
yourself

Can you explain it without looking?

Answer each question in your head before opening it. The later questions need you to combine ideas from several sections.

1. What does EPS measure?

The radius of the circle drawn around each point: how close another point must be to count as a neighbour. It is not the size of a cluster; clusters can be much bigger than EPS.

2. What makes a point core?

Its EPS circle holds at least min_samples points, counting itself (scikit-learn's rule).

3. What is the difference between a border point and a core point?

Both belong to a cluster. A core point can extend the cluster to everything in its circle; a border point only joins and cannot extend it.

4. Why is -1 not a cluster?

It is the noise label: points that are neither core nor within reach of a core point. They are left out, not grouped together.

5. A point is marked noise early on, then ends up in a cluster. How?

It was not core, so it was marked noise when first checked. Later a cluster grew to a core point whose circle contains it, so it joined as a border point.

6. What happens as EPS grows larger and larger?

More points become core, clusters join, and eventually almost everything is one cluster. Too small, and almost everything is noise.

7. Why did K-Means split the two roads badly?

It draws a straight boundary between two centres, but the roads curve around each other. It also has to put the one-off reports into a group.

8. You recorded one column in metres and the other in km. What goes wrong?

EPS is a distance in the data's units, so the metres column dominates and neighbourhoods become meaningless. Use the same unit, or standardise and rethink EPS.

Transfer challenge. A colleague runs DBSCAN with the default settings on customer spend (pounds) and visits (per year) and reports "72% of customers are noise". What would you check before accepting that?
Open a model answer
  • The default EPS is 0.5. In pounds, that is 50p: almost nobody has a neighbour. Were the columns standardised?
  • Even after scaling, was EPS chosen from a k-distance chart, or just left at the default? scikit-learn's reference notes that EPS is the most important setting to choose for your data.
  • Is min_samples sensible for the size of the data?
  • Plot the data. Are there any crowded areas at all, or is it one diffuse cloud?
  • If the groups have very different densities, try HDBSCAN.
  • "Noise" means "not in a crowded area at these settings", not "bad customers".

Words used in this guide

Every technical term used in this guide, in plain English, in alphabetical order.

TermWhat it means
ArrayA grid of numbers, like a table with no column names. scikit-learn models take their input as an array. .to_numpy() turns a pandas table into one.
Border pointA point that is not crowded itself but sits inside the circle of a core point. It joins that cluster but cannot extend it.
ClusterA group of rows that the method has decided belong together.
ClusteringFinding groups in data when nobody has said what the groups are. It is a kind of unsupervised learning.
Core pointA point whose EPS circle holds at least min_samples points, counting itself. Core points build and extend clusters.
CrosstabA count table: how many rows have each combination of two columns. pd.crosstab makes one.
DataFramepandas' name for a table: rows and named columns, like a spreadsheet inside Python.
DBSCANDensity-Based Spatial Clustering of Applications with Noise: a method that groups points in crowded areas and leaves isolated points as noise.
DistanceHow far apart two rows are. Both guides use straight-line (Euclidean) distance: square the gap in each column, add the squares, take the square root.
EPS (epsilon)The radius of the circle drawn around each point. Written eps in code. It is measured in the same units as the data.
FeatureA column used as input to the method, such as spend or km east. Label columns like a customer letter are not features.
FitRun the method on your data so it can learn from it. .fit(X) is where the actual work happens.
HDBSCANHierarchical DBSCAN: a related method that does not need a single EPS and copes with groups of different density.
k-distance chartEach point's distance to its k-th nearest point, sorted and plotted. Here k is set equal to min_samples. A sharp upward bend suggests a value for EPS.
LabelThe group number the method gives each row, stored in labels_. It is a name tag (0, 1, 2 …), not a meaning.
min_samplesHow many points make a crowd: the smallest number of points, counting the point itself, that an EPS circle must hold for its centre point to be core.
NeighbourhoodEverything inside a point's EPS circle.
NoisePoints that are neither core nor inside a core point's circle. They get the label −1 and belong to no cluster.
OPTICSA related method that orders points by density so clusters at different densities can be read off.
pandas / pdThe Python library for working with tables. pd is the usual short name for it.
ParameterA setting you choose before running a method, such as n_clusters, eps or min_samples.
RowOne record in the table: one customer, one pothole report.

scikit-learn / sklearnThe Python library that provides K-Means, DBSCAN and many other methods. It is imported under the name sklearn.
Standard deviationA measure of how spread out a column's values are: roughly, the typical distance of a value from the column's average. Small means values are bunched together; large means they are spread out.

What if one EPS cannot fit every group?

DBSCAN uses one neighbourhood size for the whole dataset. That works well when groups have a similar level of density. But if one group is packed tightly and another is spread out, the same setting can miss the spread-out group or merge areas that should stay separate.

HDBSCAN looks at how the groupings change across many neighbourhood sizes, then keeps groups that stay together over a wide range. That can help when different parts of the data have different densities, without asking you to find one EPS that suits every group.

Keep DBSCAN when its one setting describes the data clearly. Try HDBSCAN when one setting cannot do that. HDBSCAN still depends on sensible features and a minimum group-size choice; it does not decide whether a group is meaningful in the real world.
